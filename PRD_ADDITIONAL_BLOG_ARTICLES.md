# PRD: дополнительные SEO-статьи NextGen AI

## 1. Задача

Создать ещё 30 самостоятельных русскоязычных статей для блога NextGen AI на тему B2B-продаж, лидогенерации, рассылок, телемаркетинга, SaaS-продаж и партнёрского маркетинга.

Статьи должны привлекать органический трафик по конкретным информационным и коммерческим запросам, отвечать на реальную проблему пользователя и вести его к обсуждению собственной B2B-задачи с NextGen AI.

Рабочая директория: `/Users/akula/Documents/сайт некстген 300`

Продакшен: `https://nextgenrussia.ru/`

Стек: статический HTML, CSS, SVG, GitHub Pages. Не превращать проект в React/Next.js и не менять существующую архитектуру.

- `ИИ-агенты для холодных продаж` имеют нулевую подтверждённую частотность. Не делать отдельную страницу только под этот запрос. Использовать как вторичную формулировку в статьях про ИИ-продавца, SaaS и продажи без холодных звонков.

## 4. Формат каждой статьи

Каждая статья должна иметь следующую структуру:

1. SEO Title с основным ключом.
2. Meta description с основным ключом и конкретной пользой.
3. Canonical URL в формате `/blog/<slug>/`.
4. Один H1 с основным ключом.
5. Первый абзац с естественным употреблением основного ключа.
6. Визуальная обложка или SVG-схема рядом с вступлением.
7. Блок `Короткий ответ` на 40-80 слов. Он должен отвечать на вопрос пользователя напрямую и быть понятным без остального текста.
8. 3-5 H2, сформулированных языком запроса пользователя.
9. Практические примеры, чеклист или пошаговая схема.
10. Связь с B2B-аутричем, лидогенерацией, продажами или автоматизацией, если это естественно для темы.
11. CTA NextGen после полезной части, без агрессивного давления.
12. Раздел `Продолжить по теме` с минимум 4 контекстными ссылками.
13. `BlogPosting` и `BreadcrumbList` в JSON-LD.
14. Open Graph: `og:title`, `og:description`, `og:url`, `og:image`.
15. `<meta name="author" content="NextGen AI">`.

## 5. Правила содержания

### Нужно

- Писать по-русски, простым профессиональным языком.
- Отвечать на реальную проблему, а не пересказывать определение.
- Давать конкретные критерии, шаги, ошибки и примеры.
- Использовать реальные кейсы NextGen как контекст, если они действительно подходят.
- Отделять подтверждённые цифры от рекомендаций.
- В конце статьи давать понятный следующий шаг.
- Использовать синонимы естественно: лид, заявка, контакт, квалификация, B2B-клиент, встреча, воронка.

### Нельзя

- Писать публичные редакторские заметки: «источник фактов», «поисковый угол», «внутренняя документация», «собрано из Notion», «данные для SEO».
- Выдумывать цифры, клиентов, конверсии, бюджеты и результаты.
- Делать отдельные страницы под почти одинаковые формулировки.
- Повторять один и тот же текст с заменой ключевого слова.
- Набивать статью ключами механически.
- Обещать гарантированный результат или конкретное число лидов без фактического кейса.
- Делать статью только из общих советов без конкретной механики.
- Писать про массовый спам как про основную стратегию.
- Использовать английский термин без объяснения на русском.
- Добавлять фиктивные отзывы, имена клиентов и логотипы.

## 6. Визуальные требования

У каждой новой статьи должен быть минимум один визуал:

- SVG-схема процесса;
- схема воронки;
- схема сравнения каналов;
- схема квалификации лида;
- схема «проблема → действие → результат».

Можно переиспользовать существующие SVG, если тема совпадает. Если создаётся новый SVG:

- размер viewBox 1200×600;
- тёмная палитра NextGen;
- фиолетовый основной акцент и умеренный салатовый сигнал;
- текст внутри SVG должен быть коротким;
- у `<img>` обязателен описательный `alt`;
- под SVG нужна короткая функциональная подпись;
- не использовать стоковые изображения вместо полезной схемы.

## 7. SEO, GEO и AEO

Статья должна быть полезна человеку и одновременно легко извлекаться поисковыми системами:

- прямой ответ в начале;
- один самостоятельный смысл в каждом абзаце;
- H2 в форме реальных вопросов;
- конкретные цифры только с понятным контекстом;
- нормальный HTML: `main`, `article`, `header`, `section`, `nav`, `figure`, `figcaption`;
- JSON-LD `BlogPosting` и `BreadcrumbList`;
- открытый текст без JS-гейтинга;
- доступный `alt` у изображений;
- ссылки на 4-6 близких материалов;
- один основной интент на страницу.

Не добавлять `llms.txt` как гарантию попадания в AI-выдачу. Приоритет: индексируемость, оригинальный опыт, ясная структура, авторство, внутренние ссылки и реальные упоминания бренда.

## 8. Перелинковка

Каждая статья должна ссылаться:

- на 2-3 материала из текущего блога;
- на 1-2 новые статьи из соседнего кластера;
- на хаб `/blog/guides-b2b/`;
- на CTA NextGen.

Анкоры должны описывать содержание ссылки. Не использовать 20 раз одинаковый анкор «читать далее».

Примеры связок:

- B2B-продажи → воронка → квалификация → стоимость лида;
- email-рассылка → холодный email → Telegram → SMS;
- телемаркетинг → холодные продажи → первичный контакт → follow-up;
- SaaS-продажи → B2B-услуги → партнёрские продажи;
- партнёрский маркетинг → партнёрская программа → кейсы ремонта, окон и мебели.

## 10. Приёмка

Перед завершением проверить:

- 30 новых папок и `index.html` внутри каждой;
- 30 уникальных Title и H1;
- 30 уникальных meta description;
- основной ключ есть в Title, H1, description, первом абзаце и URL;
- у каждой статьи есть SVG/изображение и `alt`;
- у каждой статьи есть JSON-LD;
- нет битых внутренних ссылок;
- все новые URL есть в sitemap;
- `xmllint --noout sitemap.xml` проходит;
- `xmllint --noout assets/blog/illustrations/*.svg` проходит;
- `npx prettier --check assets/blog.css blog/index.html blog/*/index.html` проходит;
- `git diff --check` проходит;
- локальный браузер открывает блог, хаб и минимум 3 новые статьи;
- в консоли браузера нет ошибок;
- публичный текст не содержит редакторских заметок и упоминаний внутреннего источника.

## 11. Результат

Готовый результат должен быть статическим SEO-блогом NextGen с 30 новыми страницами, понятным хабом, реальной семантикой, SVG-визуалами, JSON-LD, рабочей перелинковкой и обновлённым sitemap.

После локальной проверки изменения можно коммитить в `main` и запускать GitHub Pages deployment.
